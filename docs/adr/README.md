# Architecture decision records

ADRs preserve decisions that constrain later scientific or engineering work. Read accepted ADRs
before changing the affected architecture; use the [ADR template](ADR-TEMPLATE.md) for a new decision.

## Decision index

| ADR | Status | Decision |
|---|---|---|
| [ADR-001](ADR-001-canonical-runtime.md) | Accepted | Canonical runtime and operational data integrity |

## Policy

- Use the next available three-digit number and a short kebab-case filename.
- Keep `Status` one of `Proposed`, `Accepted`, `Deprecated`, or `Superseded by ADR-NNN`.
- Record alternatives, evidence, scientific consequences, migration, rollback, and unresolved risks.
- Do not rewrite an accepted decision. Add a superseding ADR and update this index.
- Code comments may link to an ADR but do not replace one.
